# 多用户登录系统 PR 需求

来源：用户要求线上版增加登录系统，并明确选择多人使用，每人自行输入 AI API Key、Base URL 和模型名称，并保存到数据库。

- 用户名密码注册、登录、退出、修改密码；持久化、可撤销、有期限的 HttpOnly 会话。
- 未登录不能读取或修改词库、学习状态、AI、导入导出、备份恢复等业务接口。
- 每个账号的词库、FSRS、统计、设置、AI 缓存、备份及恢复完全隔离。忽略客户端伪造的 userId。
- 注册创建空学习空间。既有单人数据通过服务器 CLI 明确认领，不能由第一个公网注册者自动获得。
- 每人可以设置自己的 OpenAI 兼容 API Key、Base URL、模型名称；密钥加密入库，不返回浏览器、不写日志、不包含在学习备份中。平台 .env 的 AI 密钥不自动共享给其他用户。
- 密码安全哈希、登录/注册限流、会话和 CSRF 保护；自定义 AI 地址不能访问内网、回环或云元数据服务。
- 保留 Google Cloud IP 测试所需的显式监听/来源配置和 HTTP UUID 回退。默认安全 Cookie；仅显式配置才允许 HTTP 测试。
- 注册/登录页、账号信息和退出、修改密码、个人 AI 设置；过期会话返回登录页且移除旧账号页面状态。
- 提供升级、既有数据归属、凭据恢复、备份和部署说明，保持 SQLite，不在此 PR 实施 Cloudflare/D1 迁移。
- 测试两账号数据/备份/AI/恢复隔离、未登录拒绝、密码/会话撤销、AI 密钥不泄露、既有数据保留及 SSRF。

## 后续用户调整：词汇导出

设置页不再提供完整数据库备份/恢复入口，也不展示数据库路径。改为下载当前账号全部单词的 CSV，仅有 word（单词）、zh（中文释义）两列；空词库仍有完整表头，不含账号、AI 配置、复习日志或 FSRS 状态。管理员灾难恢复流程与服务器上的学习数据保留不受此界面调整影响。
